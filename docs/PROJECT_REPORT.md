# 头痛日记实验项目工作报告 — 0.6.1

更新日期：2026-10-18。面向临床协作者、开发者、语言审校者及项目评估者。本报告整合现有实现与后续验证计划；技术测试不构成临床验证。

## 项目目标

构建以成人头痛随访为设计场景的多语言记录与摘要原型，让患者能连续记录，医生能理解记录覆盖率、症状负担、实际用药与治疗调整。核心成果为**八语言患者日记、患者自主提醒、跨语言随访摘要、模拟医患工作区和公开合成一致性测试**。

原始需求包括头痛部位、性质、持续时间、发作频率、诱发因素、药物响应、多语言、网页邮箱登记、小程序扫码，以及周/月汇总和机构共享。现阶段按可独立验证的模块推进。代码采用源码可见许可，机构与商业使用需事先书面授权，见 [许可政策](LICENSING.md)。

## 亮点功能：患者自主提醒

提醒模块以支持持续记录为设计目标，将患者自主选择与减少不必要打扰结合起来：自选提醒日、时间及时区、消息语言和内容；提供免打扰、暂停、每日去重和当天状态填写完整后跳过。患者可主动启用或关闭，提醒授权独立于临床共享，联系方式及历史单独加密保存。

该模块可作为实验演示和后续依从性研究的基础：当前可核验计划设置、模拟触发、跳过原因和历史记录，后续真实接入后再研究送达、打开、填写覆盖率、留存及提醒负担。**目前所有渠道均为本机模拟，未验证真实送达或依从性改善。** 详见[提醒说明](REMINDERS.md)。

## 临床记录与统计原则

**一天与一次发作分别记录。** 当天无头痛、有头痛、明确未知及没有记录不能合并。分别统计头痛天数、发作次数与急性用药天数。跨午夜、同日多次发作、持续发作、结束时间未知和重叠时段均保留明确规则。当前日的记录反映截至填写时的状态，完整日统计不把当天视为已结束观察日。

**实际用药与医生建议分离。** 急性用药保留通用名、剂量、单位、时间和可选响应随访；预防治疗保留方案及执行情况。医生模拟方案不自动成为实际服药。响应统计区分未记录、超出时间窗与有效测量，不能将缺失计作成功或失败。具体时间窗是实验规则，见数据字典。

**临床评估展开显示。** 发作表单记录部位、性质、时间及相关评估，预防执行与活动影响直接显示。没有详细事件时可先保存每日状态；自动展示但完全未触碰的初始事件表单不形成记录。填写后按字段规则补全，允许明确“未知”“无”“不适用”，不制造答案。

**诱因是待核对的观察。** 怀疑诱因与每日暴露分开；无头痛日也可记录暴露。本版不根据先后关系输出确定因果结论，也不自动诊断药物过度使用性头痛。

**报告保留分母与版本。** 例如“本期完成记录23/28天，其中8天有头痛”，而不是只呈现8天。报告包含精确日期、记录覆盖率、未知/缺失、治疗时间线、源记录修订、统计规则及术语版本。自然月与滚动28日保留为不同周期；不可隐式视为相同观察时间。

当前数据模式1、统计规则0.1.0、术语版本0.2.0。0.6.0不改变统计定义，不重写既有患者文本或报告快照。细节见 [DATA_DICTIONARY.md](DATA_DICTIONARY.md)。

## 八语言与输入边界

当前提供简体中文、英语、西班牙语、法语、俄语、阿拉伯语、印地语、乌尔都语。八个目录各有626个对应界面键。阿拉伯语和乌尔都语采用RTL，印地语采用LTR；日期、剂量、邮箱和数字范围保持可读顺序。患者侧别不随页面镜像而互换。

界面语言、报告语言与原始自由文本分别管理。语言切换不修改临床概念代码、剂量、时间或已保存原文。所有译文仍是实验草稿；字符串完整和页面排版通过不等于母语临床审校完成。审校矩阵记录状态，不虚构审校人。

语音转写和候选提取仍限中英文。印地语/乌尔都语界面不代表支持对应语音、Hinglish或Roman Urdu。新增输入配置应根据目标用户偏好和真实任务测试决定，不将语言列表转化为全球人口覆盖率声明。

## 患者与医生使用路径

患者打开概览后，在连续页面记录每日状态、发作、实际用药与预防执行。语音浮窗允许边核对原文边查看对应分区，候选必须确认后才填入，最后统一保存。漏填提示保留草稿；重复同步去重；修订冲突不自动覆盖已有记录。

医生摘要展示本期与既往变化、覆盖率、强度/持续时间、功能影响及治疗时间线。模拟医生按“评估 → 方案 → 回访”填写并确认，患者可查看和反馈。此身份切换为实验演练，不代表职业资质验证或真实处方。

设置集中管理语言、报告偏好、共享、同步、导出和实验工具。共享说明应让用户了解接收对象、范围、期限和撤销影响；回执不表示真实医生已阅读或实时监护。

## 数据与安全设计

Node.js 24本机回环服务、静态网页、SQLite与浏览器离线存储。账号资料、临床载荷和音频使用应用层加密；技术元数据并非全部加密，密钥保存在同一计算机上。无需默认外部服务；启用可选云端模型后，逐次授权的内容会向指定供应商发送。

模拟医院采用独立接收存储、加密数据包、传输ID、回执和重试。真实部署还需机构身份匹配、HTTPS、权限、密钥管理、备份恢复、保留策略与审计。FHIR示例只是映射示范，不能等同医院互操作或安全认证。公开材料仅保留代码与合成样例。见 [ARCHITECTURE.md](ARCHITECTURE.md) 和 [SECURITY.md](../SECURITY.md)。

## 验证与逐步推进

1. **临床定义复核：** 由独立临床协作者检查未知、缺失、跨日、计数、时间窗、冲突及治疗时间线，记录问题和版本。
2. **语言及理解：** 母语审校、临床术语复核，再进行患者任务测试；记录完成时间、错误、困难及退出原因。
3. **摘要可解释性：** 用带缺失和冲突的合成病例评估医生阅览时间、对分母的理解以及与参考判断的一致性。
4. **真实接口准备：** 邮箱、机构身份、医院接收、平台入口及安全方案分别验收。
5. **前瞻性可行性：** 在所需机构安排下研究有效记录天数、留存、补填和响应完整性。若声称治疗结局改善，应另有适合该问题的对照研究。

多语言或完整工作流本身不能证明全球首创；项目价值应以可复现规则、公开边界测试与可测量的用户改进说明。进一步工作包见 [RESEARCH_PLAN.md](RESEARCH_PLAN.md)。

## 0.6.0 患者端优化

本项目服务患者连续记录及随访反馈，不建设完整病历、病程记录或处方执行平台。新增患者转录方案与来源、实际执行反馈、前后各28天日记观察及逐项语音候选复核。语音模型仅保留接口和兼容扩展，本版不要求安装或落地识别模型。具体步骤、缺失处理、共享范围和限制见[患者工作流](PATIENT_WORKFLOW.md)。
